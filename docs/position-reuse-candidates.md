# Nect-SVG: Position再利用の実験候補

更新: 2026-10-14 UTC
状態: ユーザーが実装・試用を希望した仕様候補。4案とも残し、実際に使った感触で採否・併存・統合を判断する。完成仕様や実装済み機能の宣言ではない。

## 目的と進め方

スナップして置いたTextの位置を、別のTextにも利用したい。XY全体の追従、Xだけ揃えてYは独立、一定の間隔を保つ、図形と文字の共通移動を扱う。

ユーザーの希望: 「いっぱいノードあっても困んないだろうし、仕様候補として書いておいて暇なときに実装してくれたら使ってみて試す」

試作順の提案:

1. Text Position OUT: 現在のTextを基準にする最小の試作。
2. Null: 独立した位置コントローラーを置く試作。
3. ハンドル付きVector: 既存の値ノードをキャンバス操作する試作。
4. Reference: 他ノードの出力を選択して取り出す試作。同一レイヤーから始め、レイヤー間は評価基盤を用意してから追加する。

NullとVectorは役割が重なるが、Nullの分かりやすさとVectorの汎用性は実際に比較する価値がある。内部処理を共用してもよいが、候補を先に削らない。ノード数の最小化をユーザーの意向より優先しない。

## 共通の意味と安全条件

### 値、参照点、優先順位

- 接続元 > 数式 > 直接値、という既存の優先順位を維持する。
- 位置の出力は評価後のVector2。接続中に保持している直接値のフォールバックを出力しない。
- Positionは各オブジェクトで保存された参照点の座標を意味する。Text内部でPositionが`center`というキーに保存されていても、幾何学的な中心と決めつけない。
- 可視アウトライン基準、左右・上下などの参照設定に従う。Aの右端をBの左端に揃える場合、AとBそれぞれの参照点を設定して同じ座標を与える。
- UI上で一時的に選んだハンドルによって、Position OUTの意味を変えない。参照設定を変更するときの既存動作も維持する。
- 数式にノード名やレイヤー名の文字列参照を追加することは、この試作の前提にしない。

### Xだけの同期、間隔

- XY追従: A.Position → B.Position。
- Xのみ: A.Position → Separate Vector.X → Combine Vector.X。Combine Vector.Yは独立の直接値・数式・別ソースにする。そのVector2をB.Positionへ接続。
- XYの間隔: 出力にVector Mathの加算で[dx, dy]を加えてからBへ接続。
- Xだけの間隔: SeparateのXにScalar加算を挟んでからCombine。
- 接続されたBのPositionの片側だけを直接編集する新しい優先順位ルールは作らない。片軸の独立性はCombineで明示する。

### 編集とスナップの持ち主

- Text OUTではA、NullではNull、ハンドル付きVectorではVectorが共有位置の編集元。
- 追従先Bのドラッグから、接続をたどってAの値を勝手に変更しない。接続・ロック中の編集制限を守る。
- Bだけ動かしたい場合は明示したオフセットを操作する。最初のText OUT試作では自動オフセット挿入も行わない。
- スナップは編集元の数値を更新する操作。スナップ先オブジェクトへの永続的な依存関係を自動生成しない。
- 将来、追従先から共有元を編集するUIを設けるなら、共有元と影響対象が見える明示操作にする。

### 座標空間とTransform

- 最初のPosition OUTは、Text生成時点の座標。下流のTransformによる位置変更は含めない。キャンバス表示のズーム・パン座標とも区別する。
- Aから二つのTransform枝が分かれると、Aの最終表示位置は一意ではない。A.Positionから「最終キャンバス位置」を推定しない。
- AとBをまとめて動かしたい場合は、両方をJoinした後にTransformする。共有のPositionと共有のTransformは別の用途。
- 特定のTransform後の位置を参照したい場合は、その枝と変換段階を明示するPoint/Anchor出力または問い合わせ機能が別途必要。これは今回の最初の試作に含めない。
- 異なるTransform枝や将来のレイヤー変換をまたぐ場合、同じVector2値でも画面上の一致は保証されない。Referenceは空間を明示し、必要な変換を定義してから対応する。

### 依存、名前変更、削除

- 接続とReferenceはどちらも評価依存として扱う。自己参照・間接循環を拒否し、不正な保存データも検出する。
- 接続は安定したノードIDと出力ポートIDで保持する。名前変更で切れない。
- 削除は既存の通常接続の方針と整合させる。フォールバックへ戻す場合もUI上で切断と使用値を分かるようにし、別の同名ノードへ自動的に付け替えない。
- Referenceの未解決ターゲットは明示する。レイヤー間Referenceでは当初、解決不能を診断可能なエラーとして扱い、黙って[0,0]や最終キャッシュ値を返さない。
- Undo/Redo、複製、保存・再読込でもIDと接続を一貫させる。複製時の内部参照の付け替えと外部参照の保持を決めてテストする。

## 候補1: Text Position OUT

用途: 既に配置・スナップしたTextをそのままマスターにする。

- Textに既存のPath OUTを残し、PositionというVector2 OUTを追加。
- Position OUTは有効なPosition入力値。Pathと別の型の出力を同じノードから取り出す。
- 他Textへの追従、Xのみ同期、オフセットは既存のVector系ノードを組み合わせる。
- Text以外への一般化は後から検討できるが、最初の実装ではTextに限定する。

試用で見る点: ノードからPositionを取り出す操作が分かりやすいか。PathとPositionの取り違えがないか。Textの参照点設定と一致して理解できるか。

## 候補2: Null

用途: 文字や図形の見た目に依存しない、専用の位置コントローラー。

- キャンバス上に編集用のポイント／十字を表示し、ドラッグとスナップでPositionを設定する。
- Vector2のPosition OUTを複数のTextへ接続する。
- SVGの描画内容・書き出しには入れない。編集用マーカーとしてだけ表示。
- 最初は位置だけ。回転・スケール・親子Transform・グループ化を暗黙に持たせない。
- 入力を接続できる設計なら、通常の優先順位とロックを守り、接続中にハンドルから共有元へ書き戻さない。

試用で見る点: 名前と見た目から「位置の基準」と理解できるか。多数のNullでキャンバスが煩雑にならないか。選択時のみ表示などの表示制御が必要か。

## 候補3: ハンドル付きVector

用途: 既存Vectorを使い続けながら、数値入力だけでなくキャンバスでも座標を編集する。

- 既存のVector2出力を維持し、任意で位置ハンドルを表示する。
- 通常のVectorは方向・サイズ・オフセットにも使われるため、すべてのVectorを自動でキャンバス上の点として表示しない。ハンドル表示の明示設定または位置用プリセットを試す。
- ハンドルのドラッグ・スナップが編集するのはそのVector自身の値。
- Nullと座標変換、スナップ、ロック処理を共用できる。ただしUIの候補としては両方を試せるようにする。

試用で見る点: 汎用Vectorと座標点の区別が付くか。専用Nullより操作が自然か。将来の統合は試用結果で判断する。

## 候補4: Reference

用途: 配線を長く引かず、対象ノードと出力を選んで値を利用する。1レイヤー=1グラフでのレイヤー間参照にも発展できる。

- 初期候補は型付き出力参照。対象ノード＋出力ポートを選び、その値を出す。Text Position OUTを選択可能にする。
- 任意の内部プロパティを文字列で覗く仕組みではなく、公開された出力を契約とする。
- 同一レイヤー版から試す。Referenceを通しても循環検出、型検証、キャッシュ無効化に参加させる。
- 対象名と出力名を表示し、対象へ移動できる導線を検討する。名前は表示用で、参照の識別には使わない。
- 対象変更で型が変わる場合、接続済みの下流を無言で異なる型へ変えない。初期版はPosition/Vector2に限定する選択も可能。

レイヤー間版の実装前提:

- 安定したレイヤーID＋ノードID＋ポートID。
- ドキュメント全体の依存グラフと循環検出。非表示レイヤーの依存値をどう評価するかも定義する。
- 参照先変更に対する別レイヤーのキャッシュ無効化。
- 削除・欠落・複製・インポート時のID処理、保存・再読込。
- 出力の座標空間の明示。初期版は生成時点の座標のみで、下流のTransform後の任意枝や見かけの位置を自動解決しない。

試用で見る点: 長い配線より読みやすいか。依存が隠れて理解しにくくならないか。レイヤー間の位置合わせが本当に必要な場面と、Join→Transformで足りる場面を区別できるか。

## 最初の実装境界: Text Position OUT

### 含むもの

1. TextのPosition Vector2ポート追加。既存Pathポートと既存の接続を維持する。
2. 入力の有効値を取り出す評価処理。Pathの評価結果とPositionを正しく区別し、型・キャッシュ・診断に反映する。
3. 出力ソケットと接続メニュー、ポートラベル、接続元表示の更新。単一出力を仮定するUIを確認する。
4. ポートIDの保存・検証・再読込。旧プロジェクトのText Path接続がそのまま動くこと。
5. 接続、切断、循環拒否、Undo/Redo、削除と名前変更の既存動作との整合。
6. 小さい試用例: マスターText＋追従Text、Xだけ同期、オフセット、共通Join→Transform。
7. 利用説明に「下流Transform前の位置」を明記。

### 含めないもの

Null、Vectorハンドル、Referenceの同時実装、レイヤー間接続、数式のノード参照、ポストTransform点の取得、自動オフセット挿入、接続先から上流を書き換えるドラッグ。

これは残りの候補を却下する境界ではなく、最初に試せる単位を小さくするための境界。

### テスト・検証条件

- TextがPathとPositionを正しい型で公開し、従来の未指定ポートのPath接続が壊れない。
- 直接値、数式、接続元の各Positionを出力し、優先順位と切断後のフォールバックが従来どおり。
- Position更新で追従Textが更新。フォント・文字列・参照点の変更時も、Position値とアウトライン変化の関係が仕様どおり。
- XY共有、Xのみ共有＋独立Y、Scalar/Vectorのオフセットがそれぞれ動作。
- Aのスナップ後にBが追従。Bの接続中ハンドルがAや接続を意図せず変更しない。ロックを尊重する。
- 自己接続、A→B→A、Vector系を挟んだ循環が拒否され、拒否時に元の接続状態が保たれる。
- Position出力を追加してもPath描画、Fill/Stroke、Join、下流Transformが回帰しない。
- 共通Join→Transformでは両者が一緒に動く。一方だけの下流TransformがText Position OUTを変えない。複数Transform枝で元Positionが曖昧に変わらない。
- 名前変更で参照維持。削除、Undo/Redo、複製、保存・再読込で既存方針と整合。
- 古いデータ読込、新ポートのラウンドトリップ、未知ポート・不正な型の拒否。新データを旧版が読めるとは保証せず、スキーマ方針を明記する。
- UIでPathとPositionを区別でき、互換型だけが接続候補になる。繰り返し接続・切断・メニュー取消・Undo後に表示と実値が一致する。
- 最終コードに対してリポジトリ指定のテスト・ビルド・静的検査を実行し、実行不能な検証は未実施と明記する。

## 現行コードの確認ポイント（変更前に再確認）

2026-10-14の読み取り時点:

- `src/core.js`の`outputPorts`/`outputType`はSeparate Vectorの複数出力を特別扱いし、その他の指定ポートを拒否している。
- 評価器`run(id, port)`もSeparate VectorのX/Y抽出を特別扱い。TextのPosition出力には評価値の取り出しとキャッシュ設計の調整が必要。
- シリアライズのパラメータ検証は`sourcePort`をX/Yに限定している。UIにソケットを足すだけでは完了しない。
- 通常接続にはノード単位の循環検出がある。最初の試作ではこれを維持し、ポート別の循環緩和を追加しない。
- 評価器はレイヤー内のノードマップを使っている。Referenceのレイヤー間対応は別の評価基盤変更となる。
- `src/main.js`のText説明は、参照点変更時にPositionを固定しアウトラインを動かすことを示している。この意味を維持する。

Text Position OUT の実験ソース、unit / DOM テスト、実 Chrome 用の受入スクリプト、`examples/text-position-reuse.json` をローカル実装した。Path を既定出力のまま保持し、追加の `position` ポートは独立した Vector2 の評価・キャッシュを持つ。詳細と互換性は product-spec 第17節を参照。実 Chrome と Windows パッケージの合格は、この変更を含む CI 結果が出てから判断する。続いてNullの位置専用コントローラーを試作した。選択時のみのキャンバスハンドル、既存スナップ、型付きPosition出力、入力駆動時の保護を含み、詳細と検証範囲は[Null Position controller](null-position.md)を参照。続いて[明示ONのVectorキャンバスハンドル](vector-position.md)を試作した。既存Value XYを共有の位置ハンドルで編集し、方向・サイズ用の通常Vectorは既定OFFのまま。続いて[同一レイヤーVector2 Reference](vector-reference.md)を試作した。安定IDと公開portの選択、依存/cycle/cache統合、欠落診断と内部参照の複製を含む。上記「現行コードの確認ポイント」は実装前の調査記録として残す。
